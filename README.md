# Lawa

Go-утилита для JSON-workflow из задач AI-агентов. Требования полного приложения:
[продуктовое описание](product/1.md).

## Что уже работает

Первый самостоятельный этап — **офлайн-проверка workflow**. Команда `validate`
проверяет обязательные поля, типы, уникальность ID, ссылки и отсутствие циклов.
Она не обращается к Codex, не создаёт запусков и не изменяет файлы.
`validate` — дополнительная диагностическая команда к командам целевого MVP.

**Исполнение пока не реализовано:** нет `run`, `resume`, `skill`, памяти запусков
и подключения к Codex App. Успешная валидация не подтверждает доступность Codex,
корректность рабочей папки, качество промптов или выполнимость задач агентами.

## Сборка и использование

Нужен Go 1.27.0 или новее; это последний стабильный релиз на 2026-08-28
([релизы Go](https://go.dev/dl/)). Версия закреплена в `go.mod`; внешних
Go-зависимостей нет. При стандартном `GOTOOLCHAIN=auto` более старый Go
загрузит нужную версию для проекта, не заменяя системную установку.

```sh
go build -o bin/lawa ./cmd/lawa
./bin/lawa help
./bin/lawa validate examples/review.json
```

Код выхода `0` означает успешную проверку/справку; `2` — ошибку. Диагностика ошибок
пишется в stderr, успешный результат — в stdout. Нужен ровно один JSON-объект;
неизвестные поля, другой регистр имён, повторные ключи и зависимости отклоняются.
`dependsOn` обязателен: `[]` допустим, пропуск и `null` — нет. Строки не исправляются
автоматически: повреждённый UTF-8 и непарные суррогаты в JSON отклоняются.
Пример специально записан не в порядке выполнения: метрики →
два независимых ревью → сборщик, ожидающий оба ревью.

## Проверки и устройство

```sh
go test -race ./...
go vet ./...
```

`internal/workflow` содержит общую проверку схемы и графа без побочных эффектов.
Разбор выполняет стандартный `encoding/json/v2`: он отклоняет неоднозначный JSON
и читает до EOF. Проверки обязательных полей и графа остаются в нашем `Validate`.
`cmd/lawa` отвечает за аргументы, чтение файла и вывод. Будущий исполнитель должен
использовать ту же проверку до создания задач и отдельно проверять среду и подключение.
Оставшиеся интеграционные вопросы описаны в [проверке Codex](docs/codex-integration.md).
