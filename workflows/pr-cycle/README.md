# Задача → готовый PR

[workflow.json](workflow.json) повторяет простой цикл: реализация и публикация PR →
независимое ревью → исправление блокеров → новое ревью. При APPROVE завершается.
Merge, deploy и release не выполняются; комментарии в GitHub не публикуются.
Итог ревью и история итераций остаются в памяти запуска Lawa.

```sh
lawa run /absolute/Lawa/workflows/pr-cycle/workflow.json \
  --cwd /absolute/project \
  --task 'https://github.com/owner/repo/issues/123'
```

Замени путь проекта и ссылку на задачу. Если PR уже существует, добавь его URL
в `--task`: доработки продолжатся в нём. Нужны авторизованные Codex CLI и `gh`,
доступ к репозиторию и скиллы solve/review (проектные или из каталога агента).
Используй выделенную рабочую папку без параллельных изменений.
Модель и reasoning effort наследуются из настроек Codex.

Запуск разрешает разработчику commit, push, создание/обновление PR и исправление
подтверждённых блокеров без ручного согласования каждого замечания. Ревьювер
работает read-only. Только P0/P1 возвращают задачу; P2/P3 не продлевают цикл.
Ревьювер не читает прежние замечания и опровержения. Отдельный кубик result
сверяет снимок и CI, затем выбирает маршрут через choose_decision.

Успех означает: опубликованный PR, APPROVE для текущих base/head и успешные
обязательные CI-проверки. Это не заменяет отдельную ручную или продуктовую QA.
Максимум пять итераций. При внешней блокировке, смене снимка, необходимости
решения человека или исчерпании лимита — failed с причиной в памяти. Workflow
не ждёт ответа человека автоматически. После терминального failed нужен новый
запуск с исходной задачей и существующим PR; resume не переигрывает решение.

Проверить конфигурацию без запуска агентов:

```sh
lawa validate workflows/pr-cycle/workflow.json
```
