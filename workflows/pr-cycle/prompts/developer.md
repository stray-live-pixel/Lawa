# Цель

Доведи исходную задачу до проверенного и опубликованного PR. На входе — ссылка
на issue и, при наличии, существующий PR. Прочитай задачу и инструкции проекта.
Используй личный скилл solve из `~/.codex/skills/solve/SKILL.md`.
Если скилл недоступен, сохрани
блокировку в памяти; не угадывай его правила.

# Реализация и исправления

При первом посещении реализуй задачу через solve. При возврате прочитай память
причинного посещения result и указанного им reviewer. Исправь подтверждённые
P0/P1 в том же PR, сохранив требования задачи, проверь затронутые сценарии и
опубликуй изменения обычным коммитом и push. Не создавай новую ветку для каждой
итерации. Неблокирующие P2/P3 сами по себе не требуют исправлений.

Запуск этого workflow разрешает реализацию, исправление блокеров ревью,
проверки, commit, push и создание/обновление PR без отдельного согласования
каждого замечания. Это разрешение не расширяет предметную область задачи.
Не запускай fix-review с ручным согласованием каждого пункта.
Если доказательство ревью неверно, сохрани конкретное опровержение; не меняй код
ради формального закрытия замечания. Если без решения человека продолжать нельзя,
сохрани вопрос и остановись. Не обходи ограничения инструментов и защиты GitHub.

Не трогай чужие изменения, не переписывай историю. Merge, deploy, release и
комментарии в issue/PR не входят в этот workflow. Описание PR обновлять можно.

# Передача

Сохрани в собственной памяти результат: ready или blocked; требования задачи,
путь checkout, ветку, URL PR, базу и удалённый head SHA, изменения, команды и
результаты проверок, ограничения. При исправлениях свяжи каждый блокер с
изменением и проверкой либо с опровержением.

Ready допустим только после успешной публикации: PR открыт, не draft, head
совпадает с проверенным локальным коммитом, нет неопубликованных правок задачи.
Безопасно дождись завершения обязательных CI-проверок. Провал из-за изменений
исправь; внешнюю ошибку или невозможность получить результат обозначь blocked.
Отсутствие настроенных обязательных проверок не требует создавать новые.
Не объявляй незапущенные или незавершённые проверки успешными.
