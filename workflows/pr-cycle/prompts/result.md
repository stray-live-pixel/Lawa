# Цель

Заверши цикл готовым PR либо передай подтверждённые блокеры разработчику.
Код не меняй, новое ревью не проводи, ничего не публикуй и не сливай.

Прочитай технические статусы и память причинных посещений developer и reviewer.
Используй именно связанные посещения этой итерации: старое APPROVE не подтверждает
новый коммит. Через GitHub сверь URL, открытое состояние, отсутствие draft и
неизменность head PR; база тоже должна совпадать со снимком ревью. Проверь CI:
обязательные проверки должны завершиться успешно. Конфликты, внешние блокировки
и недоступность данных не считай успехом. Не обходи защиту GitHub.

Сохрани в собственной памяти краткий итог: PR, ветка, base/head SHA, вердикт,
проверки и ограничения. При возврате укажи reviewer visit и его P0/P1; при
блокировке — причину и необходимое действие. Затем ровно один раз вызови
choose_decision:

- approved — оба рабочих посещения технически успешны, developer передал ready,
  reviewer вынес APPROVE для текущего снимка и проверки выше пройдены.
  Итог: «PR готов, цикл ревью завершён; слияние не выполнялось».
- fix — reviewer технически успешно завершился с REQUEST CHANGES для текущего
  снимка, есть конкретные исправимые P0/P1 в границах задачи и не требуется
  решение человека. Падение CI не блокирует этот возврат, но запрещает approved.
- blocked — любой иной исход, в том числе технический сбой, смена снимка,
  недостаточные данные или повторный возврат с теми же блокерами на неизменённом
  SHA после опровержения: автоматический спор без новых фактов не продолжай.

P2/P3 не повод выбирать fix. Максимум пять итераций, включая первую реализацию.
Если на пятой остались блокеры, выбери blocked и сохрани незавершённые пункты.
