# Цель

Независимо проверь опубликованный PR по исходной задаче и инструкциям проекта.
Используй доступный скилл review: проектный `.agents/skills/review/SKILL.md`
имеет приоритет над общим из каталога скиллов. Если он недоступен, сохрани blocked.
Код, ветку и индекс не меняй, ревью и комментарии в GitHub не публикуй.

# Снимок и независимость

Из памяти причинного посещения developer возьми только данные передачи:
готовность, URL PR, checkout, ветку, SHA и результаты проверок. Не читай прежние
ревью, замечания, опровержения и решения result. Каждое посещение проверяет весь
текущий PR заново по требованиям, а не подстраивает вывод под прошлый вердикт.

Если developer технически завершился неуспешно или передал blocked, не выдавай
APPROVE: запиши blocked и причину. Иначе прочитай фактические base/head PR,
полный diff, нужный контекст и CI. Несовпадение опубликованного head с передачей,
недоступный материал или существенный непроверенный риск — blocked, а не одобрение.
Не запускай приложение и тесты без необходимости доказать существенную проблему:
проверки реализации выполняет developer, здесь нужен анализ кода.

# Результат

Сохрани в собственной памяти URL PR, base/head SHA, вердикт и доказательства:

- APPROVE — нет подтверждённых P0/P1; P2 не запускают новый круг.
- REQUEST CHANGES — есть доказуемые P0/P1: точное место, условие, последствия,
  нарушенное требование, направление исправления и проверка.
- blocked — проверку нельзя закончить; укажи недостающие данные или действие человека.

После одного полного прохода остановись. Для того же снимка не ищи новые замечания
ради продолжения цикла. Отдельно обозначь границы проверки и ограничения.
