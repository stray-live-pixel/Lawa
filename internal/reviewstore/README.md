# Файловая сущность review

`Store.Root/<reviewId>/` — единственное место хранения запуска. `reviewId` имеет
тот же формат, что runId: 32 строчных hex-символа. Это отдельный тип запуска, а не
фиктивный workflow: `meta.json` содержит `{ "kind": "review", "version": 1 }`.
Сканеры workflow проверяют `IsReview` и пропускают такой каталог.

```
<reviewId>/
  meta.json                 маркер типа для общих сканеров
  review.json               авторитетный снимок сущности (формат v1)
  store.lock                короткая блокировка сохранения
  execution.lock            блокировка на всё время работы координатора
  view.json                 прочитанная ревизия и навигация пользователя
  events/<revision>-<id>.json  отдельные атомарные события
  artifacts/prompt.md       первоначальный запрос пользователя
  artifacts/...             снимки, diff, изображения, промпты, логи, Markdown
```

Сохраняются три этапа `context`, `review`, `presentation`, попытки каждого этапа и
неизменяемая конфигурация запуска. По умолчанию модели — `gpt-6-sol/high`,
`gpt-6-astra/high`, `gpt-6-sol/high`. Конфиг разрешается **до Create**; `MergeConfig`
поддерживает последовательное наложение пользовательских значений, `ResolveConfig`
дополняет пробелы. После запуска `Update` запрещает менять конфиг, cwd и prompt.

`Update` читает последнюю версию под flock, проверяет callback и публикует новый
JSON атомарным rename с fsync. Одновременные HTTP/CLI записи не теряются. Изменения
поднимают `UpdatedAt` и `Revision`; пустой callback ничего не меняет. `SaveView`
пишет отдельно и не поднимает запись в истории. История сортируется по `UpdatedAt`.

В `Context.Tasks` первая задача основная. Тексты задач, комментариев, файлы,
фрагменты, команды и их вывод, diff и изображения адресуются через `artifacts/`.
После установки `Context.FrozenAt` начальный контекст неизменяем. Дополнительные
материалы проверки записываются в `EvidenceFiles` и `EvidenceDesigns`.
`File.LineChanges` хранит диапазоны `added/deleted/context`; это цвета diff,
а не тяжесть замечания. Координаты диапазонов и `Anchor` относятся к сохранённому
снимку. ID файлов и изображений уникальны в пределах review.

Проверка записывает `Findings` с приоритетом P0–P3 и привязками. Презентация отдельно
добавляет обзор, экскурсии замечаний, Markdown и промпты исправления. UI и внешний
комментарий используют одни доказательства. `Publications` хранит связь замечания
с внешним ID и ревизией: исполнитель отвечает за идемпотентность внешней операции.
`Activities` содержит реально наблюдавшиеся события скиллов и субагентов,
а не предположения на основе доступных инструментов.

Артефакты неизменяемы: запись тех же байтов допустима, новые версии требуют нового
пути. Проверяются относительные пути, запрещены `..`, абсолютные пути, специальные
файлы и симлинки. `os.Root` дополнительно ограничивает операции каталогом запуска.
Каталог root доверенный; lock-файлы нельзя удалять или подменять, пока Lawa работает.
Публикация нескольких файлов намеренно не является общей транзакцией: артефакт
сохраняется **до** ссылки на него в снимке. После сбоя допустим невостребованный
артефакт, но запрещена ссылка на ещё не сохранённый материал. Исполнитель должен
проверять наличие и содержимое материалов перед завершением этапа.

`AcquireExecution` не ждёт занятой блокировки. После получения lease координатор
может вызвать `RecoverInterrupted`: незавершённая работа становится `interrupted`,
сохраняются попытки и материалы. Автоматический повтор внешних действий запрещён.
`RequestStop` только сохраняет намерение, окончательное состояние пишет исполнитель.

Usage различает неизвестное (`null`) и ноль. Input включает кэш; стоимость считается
как `(input-cache)*inputRate + cache*cacheRate + output*outputRate` за миллион токенов.
Без полной разбивки или тарифа `PriceUsage` возвращает неизвестную стоимость.
Это API-эквивалент, не оплата подписки. Курс по умолчанию — 100 рублей за доллар.

Встроенные тарифы трёх моделей сохраняют источник, дату и `Pricing.Basis`: это
базовый Standard short-context API-эквивалент без надбавок за длинный контекст,
быстрый режим, регионы, запись кэша и инструменты. При известной разбивке
`Attempt.ThreadUsage` хранит группы по фактическим моделям основного агента и
субагентов; `Attempt.Usage` — их общий итог, который нельзя складывать с группами
второй раз. `Publication.ContentHash` связывает внешний receipt с SHA-256 точного
Markdown-комментария.

Для наблюдения HTTP использует `Refresh`: сохранённый `running` превращается в
`interrupted` только если удалось захватить execution lease. Живой worker и новый
`pending` не затрагиваются. Обычный `Load` остаётся чистым чтением для runtime.

`PatchView` атомарно обновляет только переданные поля навигации. Отметка
прочтения не очищает выбранную экскурсию; явная пустая строка очищает выбор.
`Create` принимает только существующую рабочую папку и сохраняет её канонический
путь, чтобы последующая смена симлинка не перенаправляла проверку на иной проект.
