# Lawa UI

Все экраны `lawa serve` написаны на React и TypeScript. Vite собирает их в
статические HTML, CSS и JavaScript. Node.js нужен разработчику; установленный Go
бинарник раздаёт встроенную сборку без Node.js, CDN или отдельного сервера UI.

## Разработка

Нужны Go из `../go.mod` и Node.js 22.12+ (ветка 22 в `.nvmrc`). Из корня проекта:

```sh
go run ./cmd/lawa serve --root /absolute/path/to/runs --listen 127.0.0.1:60800
```

В другом терминале:

```sh
cd ui
npm ci
npm run dev
```

Vite напечатает локальный адрес. Он проксирует API и ресурсы на Go; переменная
`LAWA_UI_BACKEND` меняет адрес backend. Origin и Host сохраняются, поэтому проверка
origin для удаления работает и через dev proxy. Используйте отдельное тестовое
хранилище: действия UI применяются к реальному выбранному `--root`.

## Статическая сборка

```sh
cd ui
npm run format:check
npm test
npm run build
cd ..
go build -o bin/lawa ./cmd/lawa
```

Результат — `internal/dashboard/web/`. Он хранится в Git вместе с исходниками и
`package-lock.json`: после правки UI коммитьте пересобранные файлы. CI выполняет
`npm ci`, тесты и сборку, затем проверяет отсутствие расхождений. Обычный `go build`
использует сохранённую статику; его самого недостаточно для пересборки frontend.

Можно раздавать эту папку любым статическим сервером. Для рабочих данных всё равно
нужен Go backend на том же origin: проксируйте перечисленные ниже API/ресурсы,
а `/`, `/preview`, `/graph/:run` направляйте на `index.html`. `npm run preview`
проверяет только статическую сборку; без такого прокси данные не загрузятся.

## Устройство и расширение

- `src/App.tsx` — маршруты, фильтры URL, расписание и главная страница.
- `src/components/Tree.tsx`, `RunInfo.tsx` — дерево, детали и действия запуска.
- `WorkflowGraph.tsx` — React Flow и раскладка Dagre; отдельный lazy chunk.
- `Trace.tsx` — курсорное чтение сообщений, изоляция turn, ограничение памяти.
- `ImageExport.tsx` — явный PNG-экспорт через локальный PlantUML, выбор темы.
- `Continuation.tsx` — выбор и копирование контекста в новый чат.
- `components/ui.tsx` — общие кнопки, статусы, выбор и модальные окна Gravity UI.
- `styles.css` — компоновка и токены Gravity UI для обеих тем.
- `hooks/api.ts` — последовательный polling, отмена при уходе, защита от старых ответов.
- `types.ts` — DTO API; PascalCase соответствует существующим Go структурам.

Новые библиотеки устанавливаются через `npm install <package>`. Повторяющиеся
элементы добавляйте в `components/ui.tsx` или отдельные компоненты. Доступность
диалогов (focus trap, Escape, подписи) обеспечивает Gravity UI; не заменяйте его ручным
управлением DOM. [React Flow](https://reactflow.dev/api-reference/react-flow),
[Gravity UI](https://gravity-ui.com/),
[Vite build](https://vite.dev/guide/build).

Раскладка графа зависит только от топологии: polling сохраняет масштаб и выбранный
кубик. Посещения различаются durable key; отчёт и промпт относятся к выбранному
исполнению. Поток сообщений отображается как текст; отчёт, память и промпт — как безопасный Markdown.

## Плотность интерфейса

Рабочая область занимает всю ширину и оставшуюся высоту окна. Дерево, граф и
детали разделяются одиночными линиями без вложенных рамок. Отступы задаются внутри
панелей управления и текстовых блоков; вокруг полотна графа полей нет. Вкладки
отмечают активный экран подчёркиванием и прокручиваются горизонтально на узком
экране. Рамки полей ввода, узлов и индикатор клавиатурного фокуса сохраняются.

Поиск и вкладки используют общую высоту `--panel-toolbar-height`; внутренние
поля панелей — `--panel-inset`. Строка дерева держит иконку, имя и метаданные
в одном контейнере внутри Gravity Button: так библиотека не выносит иконку
в отдельный слот и наличие тикета не сдвигает соседние строки.

## Компактные фильтры

Один список статусов атомарно задаёт `view` и `states`: «Активные» показывает
незавершённые деревья, «В работе» — выполняющиеся ветки, «С ошибками» — ошибки
среди всех запусков, «Завершённые» (`view=completed`) — деревья без живых потомков,
включая неуспешные, «Все» — полные деревья. Старые сочетания параметров продолжают
работать и явно подписываются в списке. Смена статуса сохраняет поиск, период и
закреплённый root, но возвращает первую страницу временных окон.

Период сокращён только на закрытой кнопке: внутри списка остаются полные названия.
Счётчик показывает `Filter.Matched` — число корневых workflow текущего окна, а не
кубиков. Кнопка сброса появляется при отклонении от «Активные / 24 часа» и очищает
поиск, root и страницу. При пустом дереве сброс также доступен рядом с пояснением.

## Темы и компоненты

Все элементы управления используют `@gravity-ui/uikit`, иконки —
`@gravity-ui/icons`. Radix и Lucide удалены. `components/Theme.tsx` оборачивает
приложение в Gravity ThemeProvider и задаёт русский язык встроенных элементов.

По умолчанию выбрана системная тема: `prefers-color-scheme` отслеживается без
перезагрузки. В шапке dashboard и отдельного графа доступны «Системная», «Светлая»
и «Тёмная». Выбор сохраняется в `localStorage` под ключом `lawa-theme`; при ошибке
хранилища переключение продолжает работать до закрытия страницы. Неизвестное
сохранённое значение трактуется как системное. Палитра графа, Markdown, диалогов
и popup использует те же токены; смена темы не пересоздаёт граф и его масштаб.

React Flow и Dagre остаются движком схемы: узлы используют Gravity Card, кнопки
масштаба — Gravity Button/Icon. Семантические HTML-контейнеры и безопасный Markdown
не заменяются UI-библиотекой. Экспорт PNG изначально использует текущую тему UI,
после ручного выбора тема картинки независима от переключения приложения.

Панели вкладок монтируют содержимое только при выборе, чтобы скрытая вкладка не
запускала polling и не открывала диалоги. Focus trap и возврат фокуса делегированы
Gravity Modal; подтверждение удаления сохраняется отдельным явным действием.

## HTTP-контракт

| Маршрут | Назначение |
| --- | --- |
| `GET /api/dashboard` | Дерево, фильтры, пагинация, расписание; query как на главной |
| `GET /api/preview` | Демонстрационные данные без чтения хранилища |
| `GET /api/graph/{run}` | Узлы, связи, исполнения, отчёты, промпты |
| `GET /api/trace/{run}` | Live-вывод с курсором и необязательным visit |
| `POST /api/runs/{run}/stop-and-delete` | Подтверждённая остановка и удаление; проверка Origin |
| `/memory/…`, `/events/…`, `/uml/…` | Существующие текстовые ресурсы и старые PNG |
| `GET /graph-image/{run}?theme=dark` | PNG по запросу; `light`, `download=1` |
| `/assets/lawa-logo.png` | Встроенный логотип |
| `/ui/assets/…` | Хешированные JS/CSS; долгий immutable cache |

Точные URL ресурсов и действий приходят в DTO; frontend не конструирует пути к
файлам. JSON и HTML оболочка не кешируются. Сервер возвращает 404 для неизвестных
API и ресурсов, а не маскирует их SPA-оболочкой. Пользовательские run не попадают
в сборку. `ui/licenses.json` содержит лицензии npm-зависимостей сборки.

## Markdown и результат кубика

Результат и память рендерятся через `react-markdown` + GFM. Копирование возвращает
исходный Markdown, включая заголовки, таблицы и code fences. HTML не исполняется;
изображения представлены ссылками, чтобы не загружать адреса из частных сообщений
автоматически. При отказе Clipboard API доступно ручное копирование исходника.

«Память кубика» и «Сообщения и действия» открывают модалки и читают данные только
после клика. Промпт вынесен во вкладку «Чат Codex» и сохраняет
выбор кубика/посещения из графа. Скрытые handles остаются в DOM ради геометрии
React Flow; направления рёбер обозначаются стрелками.

Для расчёта координат Dagre получает по одной связи между парой узлов:
параллельные маршруты внутри цикла могут вызывать ошибку пересечения прямоугольника.
React Flow получает исходные рёбра со всеми подписями; объединение применяется
только к раскладке и не меняет workflow.

## Сложный пример для разработки UI

`/preview?period=24h&view=all` показывает шесть демонстрационных запусков
`sp-main-migration`: параллельная работа, повторный цикл, ожидание подтверждения,
ошибка интеграции, завершение и остановка. Фильтр «В работе» закономерно скрывает
остальные состояния. Старые небольшие примеры сохранены для вложенного дерева.

Fixture `internal/dashboard/preview_migration.go` хранит снимок 15 узлов и 30
связей исходного workflow от 16.09.2026. Промпты, локальные пути и реальные
результаты не копируются. Пример не читает runstore и не запускает workflow.
`PreviewGraph` содержит полную схему и вымышленные посещения независимо от фильтра
дерева; live API это поле не передаёт. Изменение исходного файла не обновляет
fixture автоматически.

## Автоматическая раскладка графов

`graphLayout.ts` рассчитывает схему сверху вниз и отдаёт как координаты узлов,
так и маршруты рёбер. React Flow рисует рассчитанные полилинии через BaseEdge,
не заменяя обходы препятствий новым smoothstep между концами связи.
Повторные связи между одной парой кубиков объединяются только визуально; все
уникальные подписи маршрутов сохраняются. Входной Graph остаётся неизменным.

Сильно связные компоненты получают рамку «Цикл». Узлы с одинаковыми входами и
выходами внутри одного контейнера образуют «Параллельные ветки». Это структурные
группы, а не утверждение о фактическом одновременном исполнении. Обратные рёбра
DFS исключаются из ранжирования и рисуются пунктиром справа с подписью «Возврат»;
self-loop получает отдельный обход. Порядок узлов API задаёт стабильный порядок
обхода. Неизвестные концы связей не создают невидимые кубики.

Геометрия зависит только от ID и связей, поэтому смена статусов не пересчитывает
схему. Кнопка «Развернуть граф» даёт схеме всё окно без потери выбора посещения;
кнопка «Показать весь граф» подбирает масштаб. Для больших схем доступен zoom/pan.
Автоматическая раскладка уменьшает наложения, но не гарантирует отсутствие всех
пересечений в произвольном графе. Семантические бизнес-группы и отдельные узлы
финальных исходов не выдумываются: сейчас API не передаёт таких метаданных.

## JSON и Markdown запуска

Вкладка «Описание» запрашивает `/api/source/{run}` один раз при открытии.
API возвращает сохранённый `workflow.json`, `task.md` и Markdown-инструкцию каждого
кубика. Имена исходных `.md` и состав шаблонов старые run не сохраняют: `prompt.file`
и `templates` раскрываются в текст до записи snapshot. UI явно показывает это
ограничение и не читает текущие файлы рабочего каталога вместо исторических.
Это просмотр входных инструкций, а не результатов исполнения; память и отчёты
остаются в деталях кубика. Markdown доступен как безопасный рендер и исходный текст.
Preview показывает только демонстрационную топологию и заглушки инструкций,
с явной пометкой, что этот документ не является JSON для запуска.

## Статус кубика при нескольких visits

`displayVisit` выбирает активное посещение (`starting`, `running`,
`waiting_for_approval`), иначе последнее по номеру непропущенное, иначе последний
`skipped`. Созданный `pending` означает ожидание запуска; отсутствие visits —
«Ещё не запускался». Более поздняя ошибка или отмена перекрывает прежний успех.

Узел, его цвет, номер и панель деталей используют одно посещение. Режим
«Актуальное посещение» следует обновлениям новой партии. Явный выбор истории
сохраняется при polling; skipped доступен наравне с другими visits, с trigger и
решением в деталях. После возврата к автоматическому режиму применяется общий
приоритет. Стрелки остаются нейтральной топологией, а не глобальными статусами
ветвей: результат решения принадлежит конкретному посещению. Scheduler,
сохранённые snapshots и семантика skipped не меняются.

Ширина списка запусков меняется перетаскиванием правой границы и сохраняется
в localStorage (`lawa-run-list-width-percent`). Граница доступна с клавиатуры: стрелки
меняют ширину, Home/End выбирают пределы, двойной клик сбрасывает размер.
На узких экранах сохраняется вертикальная компоновка без перетаскивания.

## Компоновка рабочего пространства

Desktop использует две колонки: изменяемая по ширине боковая панель содержит
логотип, фильтры, поиск, дерево, пагинацию и настройки. Основная область начинается
с вкладок workflow; детали кубика образуют дополнительную колонку внутри графа.
Дерево прокручивается независимо от нижней панели. На экранах до 760px боковая
панель располагается над основным содержимым.

Кнопка темы показывает текущий режим и открывает меню Gravity UI с системной,
светлой и тёмной темами; сохранение выбора и слежение за ОС не изменены. Кнопка
с часами открывает расписание, включая явное пустое состояние. Легенда статусов
под графом удалена; статусы остаются на узлах и в деталях посещения.

Поиск использует короткую подсказку «Поиск…», над ним располагается одна строка
фильтров без счётчика результатов. Фон sidebar совпадает с фоном страницы.
Тикет имеет приоритет над именем workflow: до 80% строки, с многоточием при нехватке места без переноса
ID и счётчика. Раскрытые ветки отделены вертикальными интервалами, строки
кубиков компактнее; шеврон, pin и строка выбора выровнены с одинаковыми полями 2px.

Тема и расписание находятся справа в шапке sidebar. Красная точка на часах
означает наличие запланированных запусков. Логотип статичен; поиск и фильтры
не разделены линией. Сброс — кнопка с рамкой и иконкой FunnelXmark из Gravity UI.

Линии вложенности проходят через горизонтальный центр раскрытого шеврона;
компенсация внутреннего отступа сохраняет положение дочерних узлов. Кнопка
расписания имеет фиксированный квадрат 28×28px, включая вариант с точкой.

Панель пагинации создаётся только при наличии страниц. Разделитель верхней
области находится под поиском, перед деревом; под логотипом линии нет.

При ширине sidebar до 300px текст Lawa скрывается, TEST DATA сокращается
до TEST. Правило использует container query, поэтому учитывает изменение
ширины панели независимо от ширины окна.

Обе боковые панели изменяются перетаскиванием границы и имеют пределы 2–98%.
По умолчанию левая занимает 25% рабочего пространства, правая — 25% области
графа. Проценты сохраняются отдельно (`lawa-run-list-width-percent` и
`lawa-cube-details-width-percent`); старые пиксельные настройки не читаются.
Стрелки двигают границу на один процентный пункт, Home/End выбирают минимум
и максимум, двойной клик возвращает 25%. На мобильной вертикальной
компоновке разделители скрыты и сохранённая ширина не применяется.

В верхней части правой панели статус расположен перед названием, ID запуска (`runId=…`) — вплотную под названием
шрифтом 9 px с копированием самого ID по нажатию на текст. Кнопка
ChevronsExpandUpRight скрывает левое меню в обычной сетке страницы,
ChevronsCollapseUpRight возвращает его. Overlay не создаётся; правая панель
и состояние графа сохраняются. Кнопка расположена перед вкладками и остаётся доступной на каждой из них.
Высота вкладок — 32 px, название и runId копируются по нажатию; успешная запись показывает зелёный тост Gravity.
Название и ID обрезаются троеточием, полный текст доступен при наведении.

Копируемые название и runId выглядят как текст: без фона при наведении
и анимации нажатия. Клавиатурный фокус остаётся видимым.
