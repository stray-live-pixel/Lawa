# Карточки задач команды

Карточка расширяет `TeamTask` в `team.json` (`internal/runstore/task_card.go`).
Верхние `id`, `text`, `assignee`, прежние `acceptedAt/resultId/evidence` сохранены.
Поле `card` хранит требования, состояние, доказательства и историю. У старых
поручений `card` отсутствует: им не приписывается проверенная версия задним числом.
GET ничего не мигрирует и не запускает модель. Явное edit с version 0 и полными
требованиями переводит legacy-поручение на revision 1 с тем же ID, сохраняя
прежний текст и историческую приёмку.

## Полномочия и операции

`team_task` принимает `id` операции, `action`, `taskId`, `version` карточки.
Автор берётся из runtime. `id` повторяют после неопределённого ответа: точный
повтор возвращает прежнее подтверждение; другой payload с тем же ID отклоняется.
`version` меняется при операции, `revision` — при изменении требований,
назначения или зависимостей. Конкурентная устаревшая команда отклоняется.
Проверка и запись выполняются под существующим межпроцессным `team.lock`.

| Кто | action | Дополнительные поля |
|---|---|---|
| Босс | create | title, body, expected, criteria[], assignee (необязательно), priority, dependencies[] |
| Босс | edit | Полные title/body/expected/criteria; прежние условия остаются в истории |
| Босс | assign / priority / dependencies | assignee / priority / dependencies[] |
| Исполнитель | read → acknowledge → start | Актуальная version на каждом шаге |
| Исполнитель или Босс | block | reason; пустой снимает препятствие |
| Исполнитель или Босс | workspace | {path, method, limitations} |
| Исполнитель | report | result: {summary, artifacts[], links[], versionRef, checks[], limitations} |
| Другой участник, включая Босса | review | resultId, verdict: approve/changes_requested, reason |
| Босс | return | reason |
| Босс | accept | resultId, reason (собственная проверка), integration (где/как включён результат) |
| Босс | cancel | reason |
| Исполнитель или Босс | cancel_evidence | reason: прекращение работы, архив, исключение вклада |
| Босс | cancel_finish | reason: проверка безопасного исключения; исполнитель уже завершил ход |

Человек общается с Боссом; обязательной очереди приёмок нет. Для исключительного
явного вмешательства существует same-origin `POST /api/teams/{run}/tasks`: только
create/edit/assign/priority/dependencies/cancel, автор всегда human. Принудительный
статус и человеческая приёмка отсутствуют. Полной формы управления в UI нет.

Основные статусы: `todo`, `in_progress`, `in_review`, `done`. Блокер и отмена
независимы. `cancel_requested` ещё не означает исключение вклада;
`cancelled` появляется только после доказательств и решения Босса. Завершение
turn не переводит задачу в done. Предыдущая приёмка остаётся историческим фактом
даже после уточнения, устаревания файлов или отмены.

## Результаты и ограничения проверки

`artifacts` — явно перечисленные относительные обычные файлы внутри cwd заказа.
Сервер сохраняет SHA-256 содержимого: до 100 файлов, до 10 МиБ на файл,
до 32 МиБ суммарно. Абсолютные пути, выход наружу, специальные файлы и внешние
symlink недопустимы. `links` и необязательный `versionRef` — заявления агента,
сервер не скачивает ссылки и не проверяет внешнюю VCS. Достаточен результат
только со ссылками, но качество и актуальность внешних ресурсов проверяет участник.

При review/accept и перед выполнением зависимой работы проверяются заявленные
файлы. Изменение постороннего файла не влияет. Read API показывает конкретную
причину устаревания; при выдаче работы она сохраняется и зависимые задачи
возвращаются на перепланирование. Босс возвращает результат на доработку;
новый report и review дают новую основу. Тесты автоматически не запускаются.

`team.lock` защищает карточку, но внешний редактор файлов его не удерживает.
Fingerprints — наблюдаемая проверка, а не атомарный снимок filesystem и не
доказательство смыслового качества LLM. Между хэшированием и внешней записью
возможна гонка; агент обязан проверить итоговую сборку перед завершением цели.

## VCS и изоляция

Git, другая VCS и даже VCS executable не требуются. В продукте нет команд
создания worktree/clone, PR, merge или revert. Агент выбирает доступный способ
изоляции: папку, копии файлов или рабочую копию VCS. `workspace` фиксирует путь,
способ и ограничения. Это справочные сведения, не расширение доступа сервера.

Существующие личные thread и их cwd не перемещаются. Агент выполняет файловые
действия в выбранной папке явно; backend не заявляет filesystem sandbox или
гарантированный откат общей папки. Без изоляции работа разрешена с честным
ограничением и обратимым способом. Внешние файлы представляются ссылками;
для серверных fingerprints они должны находиться внутри разрешённого cwd.
Босс собирает принятые результаты средствами проекта. При отмене предпочтителен
архив. Если результат уже включён, Босс организует исключение и перепроверку
зависимостей без потери чужой работы. Публикации и deploy автоматически не откатываются.

## Доставка и контекст

Планировщик резервирует готовую назначенную карточку под `team.lock`, по
убыванию priority, затем ID среди готовых задач свободных сотрудников. Независимые сотрудники
работают параллельно в пределах общей capacity. `LockTeamActor` удерживается
весь turn: второй serve не запускает того же исполнителя. Сохранённая доставка
после рестарта наблюдается прежним recovery; неоднозначная отправка не повторяется.
Доставка, объявленное ознакомление, подтверждение revision и приёмка различимы.
Принятие предшественника/снятие блокера будит готового исполнителя без человека.

`team_task_read` читает список (limit/after) либо taskId и раздел
card/history/results/reviews/messages (offset/limit). Продолжения явные.
`team_read` содержит краткие карточки и ссылку на подробное чтение; переиспользует
сводки/архив #128. В старой schema доступны `/task <JSON>` и `/task_read <JSON>`
через team_post. Личная история не переписывается.

Новые комнаты используют явные карточки. Старые комнаты до первой явной
операции карточки сохраняют прежний учёт адресных поручений. Первая такая
операция включает новый режим, сохраняя прежние ID/приёмки и активные thread.
`team_accept` обслуживает только старые поручения и не обходит новые проверки.

## Сообщения и UI

`team_post` принимает text, необязательные taskId, replyTo, revision. Для старой
schema — `/message <JSON>`. Сообщение хранится один раз; обычная общая реплика
без адресата не будит команду. Ответ в чужой задаче допустим по адресованной
участнику исходной реплике. Неизвестные и межзаказные связи отклоняются.
`GET /api/teams/{run}/tasks` предоставляет тот же read-контракт; раздел messages
включает архив. Ответ о результате связан с первым событием карточки.

Чат показывает задачу, источник ответа и кнопку «Ответить»; выбранную связь
можно сбросить. Переход раскрывает архив и ставит фокус на оригинал. Детали
показывают текущие требования и обсуждение. В плеере используются только снимки
из видимого префикса сообщений, без live-запроса будущей версии.
Полная доска, drag-and-drop, визуальные формы управления и реестр решений #129
не входят в эту реализацию. Figma не синхронизирована по запрету вызовов workflow.

## Воспроизведение для QA

Все данные синтетические; реальные заказы не нужны. Из корня репозитория:

```sh
LAWA_TASK_BOARD_FIXTURE_ROOT=/tmp/lawa-task-qa go test ./internal/runstore -run '^TestWriteTaskBoardFixture$' -v
go run ./cmd/lawa serve --root /tmp/lawa-task-qa --listen 127.0.0.1:60935
```

Root должен быть новым/пустым. Затем в `ui`:

```sh
LAWA_UI_BACKEND=http://127.0.0.1:60935 npm run dev -- --host 127.0.0.1 --port 51935
```

ID в `/tmp/lawa-task-qa/fixture-run-id`; URL
`http://127.0.0.1:51935/office?run=<ID>`. Оба актёра blocked — модель не запускается.
Открыть чат → ответ последней реплики → оригинал в архиве → задача T-1 → детали
и комментарий → «Ответить» → сброс → связанная отправка. Проверить темы,
390×844, клавиатуру и плеер до последней реплики: будущая revision 2 не показывается.
HTTP карточки: `/api/teams/<ID>/tasks?taskId=T-1`.

Технические сценарии без VCS: `go test ./internal/runstore -run '^TestTask'`,
`go test ./internal/teamruntime -run TestBoardPublicToolsWithoutVCS`,
`go test ./internal/dashboard -run TestTaskBoardHTTPWithoutVCS`.
Тесты очищают PATH и работают в обычных временных каталогах.
