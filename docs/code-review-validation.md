# Проверка Code Review MVP

Проверка выполнялась на изолированных временных хранилищах, без изменения рабочих
запусков пользователя и без публикации тестовых комментариев во внешние PR.

## Контракт и восстановление

- `internal/reviewstore/*_test.go`: атомарная запись, конкурирующие writers,
  execution lock, доказанная потеря процесса, неизменяемые config/context/assets,
  отдельные частичные обновления просмотренной версии, CWD и безопасные пути.
- `internal/reviewruntime/*_test.go`: три отдельных Codex-сессии, structured tools,
  невозможность завершения пустым текстовым ответом, остановка до/во время работы,
  повтор неуспешного этапа, ссылки и диапазоны доказательств, Markdown из той же
  презентации, публикационные receipts и неполные метрики.
- `internal/dashboard/review_test.go`: создание API, Origin для изменений,
  безопасная выдача растровых/текстовых артефактов, запрет traversal и повторного
  запуска при занятом координаторе; review не считается повреждённым workflow.
- `cmd/lawa/review_test.go`: default UI открывает именно reviewId, явный no-ui
  не открывает сервер/браузер, конфиг и ошибки сохраняются, custom Codex executable
  записывается для дальнейших попыток.

## Настоящий Codex

Через установленный app-server подтверждены модели `gpt-6-sol` и `gpt-6-astra`
с effort `high`. Read-only model/list не создаёт чатов. Обнаруженная несовместимость
permissions исправлена: объявленный профиль также передаётся как default_permissions.

Первый сквозной пример — временный Python-проект: изменение расчёта скидки с
`price * (1 - percent / 100)` на `price * (1 - percent)` при явном требовании
`final_price(100, 20) == 80`. Реально выполнены context/sol-high,
review/astra-high и presentation/sol-high. Итог `request_changes`, P1,
сохранённые HEAD/working snapshots, требования, команды, обзор и пятишаговое
доказательство с Markdown и промптом исправления. Папка проекта не изменена.

Отдельный прогон с нативным субагентом выявил вариант события `subAgentActivity`
без `spawnAgent`. Он покрыт регрессионным тестом: дочерний агент не теряется,
отсутствующие публичные prompt/usage не выдумываются. Для прозрачного делегирования
предоставлен `review_delegate`, сохраняющий собственный запрос, модель, effort,
состояние и наблюдаемый расход отдельной дочерней сессии. Приватные rollout-файлы
Codex не читаются.

Финальный прогон создан через настоящий `POST /api/reviews`: HTTP запустил
отдельный worker, context → review → presentation завершились. Проверка вызвала
`review_delegate`: сохранён точный промпт ребёнка и его completed-состояние;
usage проверки содержит две группы (родитель и ребёнок), все три этапа имеют
полные фактические input/cache/output. API-эквивалент примера — $0.3917904 по
зафиксированным базовым тарифам. Получены P1, обзор и экскурсия; исходники проекта
остались неизменными. Для экономного smoke использовались явно переопределённые
sol/low; согласованные defaults ранее проверены отдельным настоящим прогоном.

## Интерфейс

Проверены макетные фикстуры и настоящий сохранённый результат первого прогона:
создание, сохранение ввода при ошибке, переходы этапов и ручной возврат,
задачи/комментарии/изображения/diff/контекст проекта, выбор инструкций,
список замечаний, обзор, ошибочный участок кода, полный файл и возврат к шагу
после закрытия viewer. Используются тесты React и браузер, а не только сборка.

Размер 1280×1024 проверен целиком headless Chrome после загрузки данных;
более узкое окно сохраняет minimum width и горизонтальную прокрутку.
Цвет добавленного кода не подменяется красным при ошибке: красные маркер и
пояснение показываются отдельно. JetBrains Mono поставляется локально.

## Границы доказательств

Тарифы — датированный Standard short-context API-эквивалент, не фактическое
списание подписки. Надбавки за cache writes, инструменты, регион и fast mode
не выводятся из отсутствующих данных. Для неизвестной модели/usage нет
выдуманной нулевой цены; происхождение расчёта доступно в UI.

Публикация в произвольную инфраструктуру выполняется агентом через её настроенные
инструменты. Локально проверены контракт, Markdown, receipt, revision и защита от
дубликатов; реальные права конкретного удалённого сервиса пользователя не
подтверждаются тестовым double. Недоступность интеграции остаётся явной ошибкой,
при которой локальный результат продолжает быть доступен.
