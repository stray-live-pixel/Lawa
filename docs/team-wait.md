# Ожидание сотрудника

`room.actors[id].wait` — публичная причина, источник (`runtime` или `actor`),
время начала `since` и, для заявления сотрудника, `actorId`, `messageId`, `text`.
Эти данные доступны в офисе и `team_read`. Терминальные статусы workflow не меняются.

Runtime различает отсутствие адресных сообщений, очередь запуска, занятые слоты,
ошибку и необходимость разрешения/взаимодействия с Codex. Capacity — последнее
подтверждённое наблюдение планировщика, а не предположение UI. Оно снимается
при резервировании доставки. Восстановленный turn обновляет ожидание разрешения
по наблюдаемому статусу Codex; неоднозначная доставка по-прежнему не повторяется.

Смысл текста runtime не угадывает. Во время активного хода сотрудник сначала
отправляет сообщение нужному участнику, затем вызывает `team_post`:

```text
/wait {"kind":"result","actor_id":"reviewer","message_id":"ID своего вопроса","text":"Нужен отчёт проверки"}
```

`kind`: `result` (результат/ответ), `acceptance` (приёмка Боссом), `permission`
(явное разрешение). Для приёмки нужна ссылка на свой отчёт Боссу и непринятое
поручение. `/wait {}` снимает заявление. Команда совместима со старыми thread,
где набор dynamic tools уже закреплён. Она не публикует сообщение и не будит модель.

Заявление хранится как `dependency` до завершения текущего хода, затем показывается
как причина ожидания. Ответ указанного участника после исходного сообщения снимает
ожидание результата/разрешения. Приёмка точного отчёта снимает ожидание приёмки.
Новая доставка сбрасывает старое заявление: при необходимости сотрудник подтверждает
его заново с учётом новых входов. Достижение цели также снимает отметку.

Ошибки и разрешения Codex имеют приоритет над заявлением. Адресная очередь имеет
приоритет над смысловым ожиданием, поскольку работа уже готова к доставке.
Пустая очередь сама по себе не означает, что цель или поручение выполнены.

Обновление выполняется под `team.lock` вместе с изменением состояния и записью
кадра. Повтор неизменной причины сохраняет `since`; кадр содержит копию причины.
Чтение не пишет файлы и не запускает модель. Старые заказы без поля `wait` остаются
читаемыми: точная причина появится при следующем изменении runtime, без миграции GET.

Реализация: `internal/runstore/team_wait.go`, интеграция — `teamruntime/engine.go`
и `control.go`. Переходы и чистоту чтения проверяют `team_wait_test.go`,
`teamruntime/wait_test.go` и тест capacity в `message_wakeup_test.go`.
