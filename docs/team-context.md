# Контекст командного чата

Обычный `team_read {}` возвращает цель, действующие поручения в `room.tasks`,
приглашённых участников, незакрытые обсуждения, последнюю сводку и свежую переписку.
История UI, метрики, закрытые поручения и каталог личностей в ответ не входят.
Адресные поручения и чтение контекста имеют **разные** позиции: чтение не означает
доставку, понимание или приёмку. Уже переданное в личный Codex thread не удаляется.

## Чтение

- Первый вызов — снимок. Сохраняйте `cursor`; следующий `team_read {"cursor":"…"}`
  возвращает последующие события и актуальную сводку. Цель и действующие поручения
  передаются отдельным текущим снимком, включая изменения приёмки.
- `hasMore: true` требует продолжения с курсором ответа. `limit` — 1–100 событий,
  по умолчанию 100. Ответ дополнительно ограничен общим бюджетом.
- Позиция события — индекс в append-only журнале + 1. Порядок определяет
  `team.lock`, а не часы автора. Запись `team.json` атомарна с fsync; чтение видит
  целиком старую или новую версию. Старые заказы получают позиции без миграции.
- Курсор привязан к заказу, режиму и ID последнего события; архивный — также
  к фильтру. После сжатия непрочитанного прошлого, повреждения курсора или
  усечения журнала возвращается `resetRequired`: повторите `{}`.
  Пропущенное прошлое доступно явно в архиве; молчаливого перескакивания нет.
- Архив: `{"archive":true,"from":1,"through":80}` (обе границы включены) или
  `{"archive":true,"ids":["source-id"]}`. Сохраняйте фильтры при продолжении.
  Полный журнал запрашивается явно: `{"archive":true}`, затем страницы.
  Неизвестный ID исходного запроса — ошибка, не пустое успешное чтение.
- События не режутся. Непомещающееся событие обозначено в `notice`;
  прочитайте его по ID в архиве, затем явно используйте `resumeCursor`.
  Архив имеет отдельный потолок 65536 оценочных токенов на страницу.
- Если уже цель и действующие обязательства превышают бюджет, ответ сообщает
  об этом: требуется увеличить `responseTokens`. Они не отбрасываются незаметно.
  Итоговый JSON также проверяется: необычно длинные ID могут потребовать меньшего
  `limit` или большего бюджета; превышение возвращается явной ошибкой.

В старом thread схема инструментов могла остаться прежней. Совместимый путь:
`team_post {"text":"/context {\"archive\":true,\"from\":1,\"through\":80}"}`.
Это чтение, реплика не добавляется. В фиксированном workflow доступны страницы
и архив; приложение не добавляет ему Босса.

Оператор проверяет тот же read-only контракт без модели:
`GET /api/teams/{run}/context?limit=10`, `?cursor=…`,
`?archive=true&from=1&through=80`, `?archive=true&id=source-id`.
UI endpoint `/api/teams/{run}` сохраняет полный визуальный журнал;
агентские инструменты и prompt не используют его для обычного контекста.

## Автоматическая компактификация

Настройки `contextPolicy` в `team.json` (нули используют defaults):

```json
{"thresholdTokens":12000,"recentTokens":4000,"summaryTokens":2000,"responseTokens":12000}
```

Оценка — число Unicode-символов JSON / 3 с округлением вверх. Это воспроизводимая
инженерная оценка, не точный токенизатор модели. Порог меньше или равный свежему
бюджету заменяется на утроенный свежий. Остаётся **непрерывный хвост**, набранный
с конца до `recentTokens`, включая целое пограничное сообщение.

После записи и при проверке старого заказа scheduler создаёт `compaction_request`
для Босса: ID, предыдущая версия и фиксированный диапазон. Адресная очередь будит
Босса без новых сообщений человека; занятый Босс получает запрос после текущего
хода. Команда продолжает работу. Адресная доставка также разбита на порции до
50 сообщений / около 4000 токенов; первое сообщение всегда передаётся целиком.

Босс читает предыдущую сводку и **все** архивные страницы диапазона. Он сохраняет
ограничения, договорённости, открытые вопросы, блокеры, обязательства, результаты,
артефакты, существенные причины замены решений и ID источников. Предложение не
становится решением; незакрытый вопрос переносится из старой сводки. Новая сводка
заменяет прежнюю, а не бесконечно дописывает её. Смысловую полноту оценивает Босс;
сервер не может детерминированно доказать качество текста модели.

Команда `team_post`, доступная и старым threads:

```text
/compact {"requestId":"compact-…","through":80,"text":"Новая сводка","sourceIds":["source-id"]}
```

Только работающий Босс комнаты может публиковать сводку. Сервер проверяет запрос,
предыдущую версию, границу, источники и бюджет. Событие `compaction` и снятие запроса
сохраняются одной транзакцией. Повтор того же содержимого идемпотентен; другое
содержимое и устаревшая попытка отклоняются. Новые сообщения вне границы остаются
свежими. До успешной записи ничего не скрывается.

Завершённый ход без публикации создаёт одну повторную попытку. После второй запрос
получает `failed`; новые записи и рестарт не создают пустые циклы. Явное
восстановление Боссом или человеком: `/compact_retry`. Неоднозначный сетевой сбой
остаётся в обычном `blocked/recover` runtime: отправка не повторяется вслепую.
Запрошенную сводку нужно сохранить до `team_complete`: завершение не поглощает
ожидающий запрос. Уже достигнутая цель не запускает сжатие до возобновления работы
человеком. Ручной повтор с тем же ID возвращает прежний запрос без дубля.

## UI и историческое состояние

Один раскрываемый архив содержит префикс до последней опубликованной границы.
Оригиналы находятся над линией архива; сводка доступна по «К сводке Босса» и в месте
своего события. Старые сводки остаются событиями внутри архива. Источник раскрывает
cut и переводит фокус на оригинал. Сообщения не дублируются. При новом сжатии чтение
старого сообщения сохраняет видимый ориентир; polling не возвращает читателя вниз.

Плеер выбирает префикс сообщений исторического кадра, затем вычисляет последнюю
сводку **только в нём**. Будущая версия и граница не попадают в прошлое.
Оригиналы и успешные версии остаются в `team.json`.

## Воспроизведение QA без реальных агентов

```sh
mkdir -p /tmp/lawa-compaction-qa
LAWA_COMPACTION_FIXTURE_ROOT=/tmp/lawa-compaction-qa go test ./internal/runstore -run TestWriteCompactionFixture -v
go run ./cmd/lawa serve --root /tmp/lawa-compaction-qa --listen 127.0.0.1:60828
# В другом терминале:
cd ui
LAWA_UI_BACKEND=http://127.0.0.1:60828 npm run dev -- --port 51828
```

Fixture требует пустой временный root, создаёт 90 синтетических реплик, две сводки,
кадры истории и достигнутую цель. Runtime не запускает модель. ID записан в
`/tmp/lawa-compaction-qa/fixture-run-id`; URL:
`http://127.0.0.1:51828/office?run=<ID>`.

Откройте чат, перейдите к сводке, раскройте источник и закройте архив. Проверьте обе
темы, 1440×1000 и 390×844, копирование, сохранение прокрутки. На плеере проверьте
состояния до первой версии (08:40:01 UTC), между версиями и после второй (09:15:01 UTC).
Не нажимайте восстановление из Codex: fixture содержит кадры, это не модельный опыт.

Технические сценарии: `go test ./internal/runstore ./internal/teamruntime ./internal/coordinator ./internal/dashboard`
и `cd ui && npm test`. Управляемый клиент проверяет настоящий scheduler и dynamic
tools, но не подтверждает качество реальной LLM-суммаризации.

Переходы к сводке, источнику и причине ожидания показывают начало сообщения
под закреплённой целью с учётом её текущей высоты. Длинный текст не центрируется;
фокус переходит к сообщению, прокручивается только чат. Для проверки используйте
сводку и исходник длиннее высоты телефона, затем повторите с раскрытой целью.
