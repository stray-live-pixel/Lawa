# Статистика размера кода

Этот документ хранит сопоставимые снимки размера Lawa. Новые снимки нужно
добавлять в историю, не заменяя прежние: так видно, какие части приложения растут
и как меняется соотношение продуктового кода и тестов.

## Правила подсчёта

Основная метрика — **строки кода**: непустые строки, в которых есть что-то кроме
комментария. Дополнительно фиксируются физические строки, включая комментарии и
пустые строки. Все значения относятся к конкретному Git-коммиту.

В продуктовый код входят:

- Go-файлы приложения без `*_test.go`;
- Go-бэкенд и встроенный HTML/CSS/JavaScript Dashboard;
- поставляемый пользователю `install.sh`.

Отдельно считаются и не входят в основную сумму:

- Go-тесты `*_test.go`;
- лендинг `index.html`, `assets/landing.css` и `assets/landing.js`;
- документация, примеры workflow, скиллы и бинарные ресурсы.

Для Go границы комментариев нужно определять парсером Go, а не поиском `//` в
тексте: такие символы могут находиться внутри строк. Для HTML/CSS/JavaScript и shell
исключаются пустые строки и строки, содержащие только комментарий. При следующем
замере нельзя незаметно менять состав файлов или методику — иначе новый результат
нужно пометить как несопоставимый.

## Где сосредоточен код

| Модуль | Строки кода | Доля продукта | Ответственность |
|---|---:|---:|---|
| `cmd/lawa` | 1 596 | 20,2% | CLI, запуск, дочерние workflow, observability и update |
| `internal/dashboard` | 1 390 | 17,6% | HTTP-бэкенд, фильтры и интерфейс Dashboard |
| `internal/runstore` | 1 160 | 14,7% | долговечное состояние, блокировки и события запусков |
| `internal/coordinator` | 1 062 | 13,5% | подготовка и выполнение графа workflow |
| `internal/codex` | 913 | 11,6% | протокол и жизненный цикл Codex App Server |
| Остальные модули и установщик | 1 769 | 22,4% | лимиты, расписания, серии, отчёты и служебный код |

Объём исходников соответствует небольшому приложению, но сложность выше, чем
следует из одного числа строк. Основные причины — параллельное выполнение,
сохранение и восстановление состояния, файловая безопасность, внешний протокол
Codex, планировщик и Dashboard. Высокое отношение тестов к продуктовому коду
снижает риск изменений, но также увеличивает полный объём репозитория.

## Как добавить следующий снимок

1. Переключиться на точный релизный тег или зафиксировать полный SHA ветки.
2. Пересчитать те же группы файлов по правилам выше.
3. Добавить новую строку в таблицу «История», не изменяя прошлые значения.
4. Добавить новый раздел снимка, если распределение по частям заметно изменилось.
5. Проверить два равенства:
   - продуктовый код = Go без Dashboard + Dashboard backend + Dashboard frontend + установщик;
   - физические строки = код + строки только с комментариями + пустые строки.
6. В diff явно отметить любое изменение методики или состава учитываемых файлов.
