# План завершения MVP Lawa

Дата фиксации плана: 2026-08-29. Требования MVP: [product/1.md](../product/1.md).

После PR #14 план состоит из пяти отдельных законченных PR. Каждый следующий этап
начинается от актуальной `main` после слияния предыдущего. Порядок важен: поздние
этапы используют сохранённые связи и статусы, добавленные ранними.

## PR 1. Запуск подготовленной волны через Codex

Подключить `coordinator.Prepare` к клиенту Codex. Готовые кубики запускаются
параллельно; `codexThreadId` сохраняется до отправки turn, терминальный статус
переводится во внутреннее состояние Lawa. Ошибка сохранения запрещает новые запросы.

Готово, когда подставной app-server подтверждает параллельный запуск независимых
кубиков, сохранение ID и статусов без повторного создания чатов.

## PR 2. Команда `lawa run`

Добавить разбор аргументов `run`, создание папки запуска, передачу постановки,
комментария и ID чата-инициатора, запуск готовых волн, понятный вывод статусов и
обработку SIGINT/SIGTERM без отмены задач Codex.

Готово, когда новый workflow запускается одной CLI-командой, зависимости открываются
только после успеха, а пользователь получает `runId` для будущего продолжения.

## PR 3. Наблюдение существующих задач Codex

Реализовать подключение к сохранённым `codexThreadId`, чтение актуального статуса
и учёт ручного продолжения того же чата. Ошибка, отмена и ожидание подтверждения
не завершают flow и не создают новый чат.

Готово, когда сценарий «ошибка → ручное продолжение → успех» открывает зависимые
кубики без дубликатов. Это самый рискованный этап: ограничения протокола Codex App
могут потребовать разделить его ещё на один самостоятельный PR.

## PR 4. Команда `lawa resume`

Добавить открытие сохранённого run под блокировкой, сверку всех известных чатов,
восстановление после остановки процесса и запуск только действительно готовых
Pending-кубиков. Неоднозначный `Starting` должен завершаться диагностикой, а не
слепым повтором создания.

Готово, когда остановка Lawa и последующий `resume <run-id>` продолжают тот же
workflow, сохраняют память и не создают новые чаты для уже начатых кубиков.

## PR 5. Запуск из чата и сквозная проверка

Установить и проверить скилл `/lawa`, связать его с финальной постановкой из
чата-инициатора, провести сквозные сценарии с параллельными ветками, сборщиком,
ошибкой, ручным повтором, остановкой и resume. Обновить документацию установки и
известные ограничения macOS/Linux.

Готово, когда пользователь может сформулировать задачу в Codex, вызвать `/lawa`,
наблюдать отдельные задачи и успешно продолжить прерванный запуск без терминальной
ручной сборки команды.

## Правила изменения плана

- Один PR реализует один указанный законченный результат и оставляет систему рабочей.
- Следующий PR не объединяется с предыдущим только ради сокращения числа итераций.
- План меняется лишь при подтверждённом ограничении Codex App или если этап превышает
  1200 изменённых строк. Причина и новое разбиение сначала фиксируются в этом файле.
- MVP готов только после прохождения критериев всех пяти этапов, а не после появления
  отдельных команд `run` или `resume`.
