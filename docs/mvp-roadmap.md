# Реализация MVP Lawa

Дата фиксации плана: 2026-08-29. Требования MVP: [product/1.md](../product/1.md).

После PR #14 работа была запланирована пятью этапами. По явному решению пользователя
от 2026-08-29 они реализуются одной большой веткой и одним PR. Порядок внутри кода
сохранён: запуск использует постоянные связи, наблюдение — статусы, а `resume` — оба.

## Этап 1. Запуск подготовленной волны через Codex — реализован

`coordinator.Prepare` подключён к клиенту Codex. Готовые кубики запускаются
параллельно; `codexThreadId` сохраняется до отправки turn, терминальный статус
переводится во внутреннее состояние Lawa. Ошибка сохранения запрещает новые запросы.

Готово, когда подставной app-server подтверждает параллельный запуск независимых
кубиков, сохранение ID и статусов без повторного создания чатов.

## Этап 2. Команда `lawa run` — реализован

CLI разбирает аргументы `run`, создаёт папку запуска, передаёт постановку,
комментарий и ID чата-инициатора, запускает готовые волны, выводит статусы и
обрабатывает SIGINT/SIGTERM с адресной отменой активных turn.

Готово, когда новый workflow запускается одной CLI-командой, зависимости открываются
только после успеха, а пользователь получает `runId` для будущего продолжения.

## Этап 3. Наблюдение существующих задач Codex — реализован

Реализовано подключение к сохранённым `codexThreadId`, чтение актуального статуса
и учёт ручного продолжения того же чата. Ошибка, отмена и ожидание подтверждения
не завершают flow и не создают новый чат.

Готово, когда сценарий «ошибка → ручное продолжение → успех» открывает зависимые
кубики без дубликатов. Это самый рискованный этап: ограничения протокола Codex App
могут потребовать разделить его ещё на один самостоятельный PR.

## Этап 4. Команда `lawa resume` — реализован

`resume` открывает сохранённый run под блокировкой, сверяет все известные чаты,
восстанавливается после остановки процесса и запускает только действительно готовые
Pending-кубики. Для последнего статуса `interrupted` он отправляет один `continue`
в прежний чат; `failed` и `completed` не повторяет. Неоднозначный `Starting` должен
завершаться диагностикой, а не слепым повтором создания. Подтверждённый отказ до
`thread/start` возвращает шаг в `Pending` и рекомендует агенту повторить тот же run
явной командой `resume` после устранения ошибки Codex.

Готово, когда остановка Lawa и последующий `resume <run-id>` продолжают тот же
workflow, сохраняют память и не создают новые чаты для уже начатых кубиков.

## Этап 5. Запуск из чата и сквозная проверка — реализован и проверен на macOS

Готовый скилл `/lawa` связан с финальной постановкой из чата-инициатора. Автотесты
проводят сквозные сценарии с параллельными ветками, сборщиком, ошибкой, ручным
повтором, остановкой и resume. Документация установки и известных ограничений
macOS/Linux обновлена.

Команда `skill` печатает готовый устанавливаемый `SKILL.md`, а README описывает
установку. Автотесты покрывают параллельные ветки, сборщик, ошибку, ручной успех,
сигнал и `resume`. Три живых пятикубиковых запуска 2026-08-29 проверили на macOS
задачи в Desktop, ручное продолжение, Ctrl+C и автоматический `continue` в том же
чате. Linux остаётся ручной платформенной проверкой перед выпуском Linux-сборки.

## Решение об объёме PR

- Полный diff намеренно превышает прежний блокирующий ориентир 1200 строк.
- Пользователь заранее подтвердил большой единый PR после предложения разбить работу.
- Тесты, обработка ошибок, комментарии и документация не сокращаются ради размера.
- Публикация всё равно выполняется отдельным этапом `$commit`; этот документ не даёт
  разрешения на push или merge.
