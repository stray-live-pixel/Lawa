# Реализация MVP Lawa

Документ отражает текущий app-server-only runtime. Архитектурное обоснование и
миграция описаны в [codex-integration.md](codex-integration.md).

## Реализовано

- строгий JSON workflow и проверка DAG;
- атомарное резервирование готовой волны;
- отдельный App Server и thread на кубик;
- параллельный запуск независимых кубиков;
- сохранение thread/turn до ожидания результата;
- reconcile через read-only `thread/read`;
- точечный `turn/interrupt` и безопасный `resume`;
- память кубиков и локальные Markdown/PlantUML-отчёты;
- повторяющиеся серии immediate/after/cron;
- связанные run через `parentRunId`;
- `status`, нормализованные `logs` и read-only dashboard;
- PID/exit/signal и безопасные lifecycle-события;
- установка и обновление бинарника и скилла на macOS/Linux.

## Архитектурная граница

Lawa не оркестрирует workflow через задачи Codex Desktop. У приложения нет
публичного API управления задачами, а управляющий агент добавляет модельные turn,
задержку, стоимость и bottleneck. Единственный runtime — прямой App Server.

## Дальнейшая работа

- нагрузочные проверки очень широких DAG и длительных серий;
- управляемый глобальный лимит параллельности;
- retention/rotation нормализованных журналов;
- дополнительные представления метрик без расширения приватного payload;
- end-to-end Linux gate в release CI;
- явная политика ручного продолжения failed turn.

Каждое расширение должно сохранять фасад CLI: пользователь не управляет RPC,
процессами, thread или turn вручную.
