## Браузер и сохранение доказательств

Эти действия нужны только для проверки UI. Не начинай их, если QA frontend
установил отсутствие frontend-изменений. Не запускай сам workflow или реальных
агентов ради получения тестового состояния.

1. Найди команды запуска и тестовые данные в README проекта и передаче разработчика.
   Для Lawa используй `ui/README.md`: backend с отдельным временным `--root`, Vite
   с proxy на него. Выбери свободные loopback-порты, проверь HTTP-ответ и загрузку
   нужных данных. `npm run preview` без backend не доказывает работу приложения.
   `/view` и офис требуют своих данных; пустой dashboard их не заменяет.
2. Выбери реально доступный инструмент браузера. Прочитай его инструкции и список
   возможностей, не угадывай названия методов. Если доступен `cua_repl`, начни
   с документированной точки входа, затем прочитай возвращённую документацию.
   Если его нет, используй доступную браузерную автоматизацию проекта, например
   установленный Playwright, по её документации. Не считай наличие браузера в
   родительском чате гарантией его наличия у автономного агента.
3. Открой точный URL, дождись нужного состояния по видимым элементам и данным,
   затем выполни действия пользователя. После навигации обновляй состояние страницы,
   не кликай по устаревшим координатам. Учитывай ошибки страницы, консоли и запросов.
   Не заменяй чтение готового интерфейса HTML-кодом или одними DOM-проверками.
4. Сохрани PNG текущего состояния поддерживаемым способом браузерного инструмента
   в отдельную папку артефактов вне рабочего репозитория. Имя включает runId,
   stepId, visitId и номер кадра. Если инструмент возвращает только превью,
   выясни документированный способ сохранения оригинала; не выдумывай путь.
   Скилл `get-screenshot`, если доступен, подходит для состояния, воспроизводимого
   отдельным URL. Его отдельный браузер не наследует выбранную вкладку, тему,
   открытое меню и другие интерактивные состояния текущей сессии.
5. Проверь, что файл существует, непустой, имеет формат PNG и ожидаемые размеры.
   Открой сам снимок и убедись, что на нём нужный экран, тема и состояние, а не
   загрузка или ошибка. Сохрани рядом краткую привязку: SHA кода, URL, размеры окна,
   тема, шаги и наблюдение. Оригинал не меняй; пояснения давай рядом с изображением
   или на отдельной копии. Недоступность разметки не блокирует отчёт с оригиналом.
6. По завершении останови только запущенные тобой серверы и браузерные процессы.
   Сохрани снимки, логи и черновик отчёта до публикации и передачи следующему QA.

При сбое сначала определи этап: запуск сервера, доступ к браузеру, воспроизведение
состояния, сохранение файла или публикация. Проверь соответствующий лог и исправь
конкретную причину в тестовом окружении, не меняя код продукта. После исправления
повтори только неудавшийся этап; готовые снимки не пересоздавай без необходимости.
Не повторяй неизменный неудачный вызов по кругу. Если разрешённого способа продолжить
нет, сохрани готовые материалы и точную диагностику в памяти, опубликуй доступный
текстовый отчёт о блокировке и выбери `blocked`. Отсутствие скриншота при такой
блокировке не мешает сообщить о ней, но исключает успешную приёмку UI.
